# Live Logs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin-only Live logs page that streams, over a WebSocket, every request, error, security denial and stream connection for the hosts they pick — from every node, stored nowhere.

**Architecture:** Each server block gets an extra syslog target, `127.0.0.1:5140` over UDP, in a MegooPM JSON format, tagged with the host's key. A stream UDP server on that loopback address in the same nginx (Lua) is the relay: it classifies each datagram, adds the node, and `PUBLISH`es it to the Redis channel `megoopm:live:<host_key>` only while that channel has subscribers. The backend's WebSocket (any node) subscribes to the channels the page asks for and forwards the messages, with rate limiting and a periodic session re-check.

**Tech Stack:** OpenResty (http + stream Lua, lua-resty-redis), FastAPI WebSocket on uvicorn[standard], redis.asyncio pub/sub, Next.js + React, vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-live-logs-design.md`. Approved mockup (layout A): `.superpowers/brainstorm/407-1792928043/content/live-logs-layouts.html` (local, untracked).

## Global Constraints

- **Nothing stored:** no DB row, no Redis key/list/stream/ticket record, no file. Redis is used only for `PUBLISH`, `SUBSCRIBE` and `PUBSUB NUMSUB`.
- Relay address `127.0.0.1:5140` (UDP), an IP literal, never a hostname. A relay or Redis that is down must never fail a request, `nginx -t`, or a reload.
- Host keys: `p<id>` proxy, `r<id>` redirection, `d<id>` dead, `s<id>` stream, `u` unclaimed (default servers). Syslog tag `mgm_<host_key>`. Redis channel `megoopm:live:<host_key>`.
- Log kinds on the wire: `request`, `error`, `security`, `stream`, `decision`.
- Errors: nginx sends at `info`. The relay keeps severity ≤ warn (syslog severity ≤ 4), plus lines matching `SSL_do_handshake() failed` or `peer closed connection in SSL handshake`. Lines containing `[Crowdsec] denied` become `security`. Everything else is dropped.
- Existing `combined` stdout and CrowdSec syslog targets keep working unchanged on every server block.
- WebSocket: browser-session admins only (`SessionAdminUser`), never API keys. A 30 s signed ticket of type `live`. Session re-check every 60 s (active, admin, `token_version` unchanged).
- Per-session cap: 200 lines/s. Over the cap, lines are skipped and a `{"type":"skipped","count":N}` frame is sent once per second.
- Browser keeps the last 1,000 lines per tab, in memory only.
- Log content is attacker-controlled (URLs, user agents): it is rendered as text, never as HTML.
- Stream lines and long-lived requests appear when they close; the Stream tab says so.

## Review Focus

1. **Relay or Redis down:** requests still return 200, `nginx -t` passes, nothing blocks. Pinned in Task 1 (harness).
2. **Hostile log content:** `<img src=x onerror=alert(1)>` in a user agent or URL renders as text, and quotes, newlines and unicode keep the JSON valid. Pinned in Task 1 (harness) and Task 4 (UI test).
3. **A busy host:** the browser stays responsive, and skipped lines show as "N lines skipped". Pinned in Task 3 (rate limiter test) and Task 4 (UI test).
4. **An admin demoted, disabled or signed out everywhere while watching:** the socket closes within 60 s. Pinned in Task 3.
5. **An oversized line:** nginx truncates syslog messages, so a request with a 10 KB URL yields invalid JSON. The line is still shown, raw and marked truncated, and never crashes the relay or the page. Pinned in Task 1 (harness) and Task 4.

**Interfaces — Produces:**
- Published message, one JSON object per line: `{"node": str, "host": str, "log": "request"|"error"|"security"|"stream", "sev": int, "f": <object from the log format> | null, "raw": str | null, "truncated": bool}`. `f` is set when the body parses as JSON; otherwise `raw` holds the text, with `truncated: true` when the body started with `{` but did not parse.
- Datagram parsing: `^<(%d+)>%a+ +%d+ [%d:]+ mgm_([%w]+): (.*)$` (sent with `nohostname`), severity = PRI % 8.
- `PUBSUB NUMSUB megoopm:live:<host>` is cached per worker in `megoopm_live` for 1 s, so a busy host costs one Redis round-trip per second while nobody watches. Redis connections use keepalive (`set_keepalive(10000, 32)`) and 200 ms timeouts.
